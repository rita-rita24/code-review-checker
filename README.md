# code-review-checker

`code-review-checker-2219.html` をブラウザーで開いて使用します。
CSS・JavaScript・favicon・解析器はすべてHTML内に含まれているため、このHTMLファイル1つだけでオフラインでも動作します。入力コードの実行・永続保存・外部送信は行いません。

## 開発・品質確認

Node.js 22以降を使用します。利用者がHTMLを開く際にNode.jsやnpmは不要です。

```sh
npm ci --ignore-scripts
npm run check:parser
npm test
npx playwright install chromium firefox webkit
npm run test:browser
```

編集対象は `src/checker.js`、`src/javascript-analysis.js`、`src/java-analysis.js` です。JavaScriptはAcornとacorn-loose、Javaはjava-parserを使用します。アプリのソースや依存バージョンを変更したら `npm run build:parser` で配布HTMLを再生成してください。実行時のCDN取得はありません。依存パッケージのライセンスを配布HTMLに同梱しています。

- `npm test`: 解析・型の推定・スコープ・修正例・状態管理・長大入力・不正入力500パターン・静的UIの回帰テスト。共有する条件式やDOM要素の1,000段の参照、未完のJava型の解析打ち切りと復帰も検査。CPU負荷を伴うテスト同士の競合を避けるため、ファイル単位では順番に実行します。
- `npm run test:browser`: Chromium・Firefox・WebKitで各32シナリオ。オフライン起動、入力操作、クリアの取り消しとやり直し、解析中断、描画、該当行への移動、フォーム復元、テーマの追従とページ間同期、結果カードのキーボード操作と読み上げ用の関連付けなどを確認。性能を測る `npm test` と同時には実行しないでください。
- `npm run check:parser`: 配布HTMLがソースとロック済み依存から再現できることを確認。
- GitHub Actions: 上記のインストール・生成一致・テストを実行。

ブラウザーテストはローカルのHTMLを開き、HTTP通信を遮断します。WebKitのオフラインエミュレーションはローカルファイルとBlob Workerも阻害するため、WebKitではHTTPリクエストの遮断によって外部取得に依存しないことを確認します。大量入力テストはtextareaの値設定とinputイベントで行い、OSのクリップボードを変更しません。

## 内部処理と対応範囲

命名・書式・一部のコード品質ルールを確認する補助ツールです。構文・型・実行結果・セキュリティの正しさを保証するコンパイラーやプロジェクト全体の解析器ではありません。

- JavaScriptは標準ECMAScriptのスクリプト／モジュールとコード断片を扱います。JSX・TypeScript・未対応の提案構文は対象外です。
- Javaは構文木と宣言スコープを使い、複数行の宣言、引数、レコード、同一入力内のフィールド・継承・戻り値などを確認します。依存ライブラリーや別ファイルの型、複雑な実行時の値までは解決しません。
- Javaのリソース変数とパターン変数の有効範囲を区別し、if・while・forの条件、短絡評価、単純なreturn／throwガードを扱います。JavaScriptの共有する型推定結果は再利用し、条件式の重複解析を抑えます。
- JavaScriptの分割代入のデフォルト値や`with`の動的な名前解決は、実際の型として断定しません。Javaの連続したメソッド呼び出し、代入式、`instanceof`と論理演算は、それぞれの式の型と優先順位を区別します。
- JavaScriptの代入式・更新式・複合代入では式の結果型を扱い、グローバル識別子への代入があれば組み込みAPIという推定を無効化します。Javaでは型注釈と型名を構文木で分離し、生成した配列の要素や外側のクラスのメソッドも追跡します。
- JavaScriptでは `globalThis.Number` などの明示的なグローバルプロパティの置換・削除と、DOM生成メソッドや `console.log` の置換も考慮します。固定文字列のテンプレートによるプロパティ参照を扱い、プライベートメンバーを公開APIと混同しません。動的なプロパティ名、別名経由の変更、外部ファイルによる置換までは追跡しません。
- Javaの解析に成功した場合、ログ出力とcatchも構文木を使って検査します。改行・コメント・注釈・修飾子を扱い、同じ入力内の独自の `System` や `Exception` と区別します。nullを含む条件式でも、文字列や配列の参照型を維持します。
- 入力途中や構文エラーでは、読み取れる部分の検査を続けます。完全に解析できなかった入力や解析失敗に対して「指摘はありません」の成功表示は出しません。構文エラー用の画面や文言は追加していません。
- 型を確定できない値は断定を避けます。ただし、未宣言の `input`・`select` などをDOM要素とみなす既存のコード断片向け規約など、一部の推定は残ります。
- 解析と結果カードの生成はWeb Workerで行います。入力変更時は古い解析を中断し、クリア時にはワーカーも解放します。大量の結果は分割描画し、行番号は表示範囲だけ生成します。
- 結果カードは既存の指摘本文を読み上げ用の説明として参照します。Enterで該当行を選択し、Shift+Tabで入力欄から移動できます。移動先はブラウザーのキーボードアクセス設定に従います。
- Javaパーサーには先読み回数と経過時間の上限を設けています。複雑すぎる入力では部分解析に切り替え、次の入力の解析を継続します。通常の解析をタイマーで強制終了する仕組みではなく、上限は応答時間を保証するものではありません。
- クリアはブラウザーの取り消し履歴を利用します。10万文字以下では直前の入力と削除が一緒に取り消されないよう履歴を区切り、巨大入力では応答性を優先してブラウザー本来の履歴のまとまり方に従います。編集APIが禁止された環境では、テキスト編集APIで操作を継続しますが、取り消し履歴は保証できません。
- テーマを手動選択するまではOSの配色変更に追従します。保存が禁止されていても、そのページで選んだテーマは保持します。保存可能な環境では同じHTMLを開いたページ間でテーマを同期し、保存設定が削除されたページではOS設定に戻ります。
- Workerが利用できない環境では同じ解析器をメインスレッドで動かします。この場合、大量入力の解析中に応答が遅くなる可能性があります。
